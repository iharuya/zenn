## あのゲージを空っぽにするまで寝られない

ClaudeやCodexの利用状況を見て、「今週まだこんなに残っている！リセットまでに全部使わないともったいない！！！」と思ったことありませんか。

サブスクはもう払っているし、使えるものは使ったほうが得に見える。

![](/images/anti-token-maxxing/chatgpt-usage-web.png)


金曜午後4時。

今週はまだ40%しか使っていない。ソワソワする。よし。

最高級モデル・思考レベルMax・並列駆動でコードベースのレビュー・リファクタを依頼。

1時間後`Rate limit reached`というメッセージを見て幸せホルモンを放出。今週もたくさん仕事したなぁ。

月曜日。20個の修正PR。全部それっぽい。そうだ、利用制限がリセットされてるから並列で全部チェックさせよう！

新たな設計案か、なんか良さそうだなー。。。

完全に依存症である。

「**トークンを使い切ることには何の価値もないよ**」

「時間と金を浪費するだけでなく、場合によっては技術負債すら残すTokenMaxxingは害悪」

ちょっと前、ある企業でエンジニアの生産性をトークン消費量で計測したらしい。すぐにそれは過ちであると[業界は気づいた](https://www.ibm.com/jp-ja/think/insights/tokenmaxxing-dead-long-live-valuemaxxing)。見るべきなのは完了したタスク、削減できた開発時間、解決した脆弱性、回避できた手戻りといった成果だと。

正論すぎる。でも、こうした説明を聞いただけでこの負のループから脱却できるなら、パチンコや競馬はこの世に存在しないはず。

あのゲージが余ってるのを見ると勝手に、プロンプトを叩いてしまうんだ！

## ゲージを壊す

理屈で治らないなら、あのゲージを見えなくすればいい。

利用率の数字をやめて、表示を雑にした。

| 利用率 | 表示 |
| --- | --- |
| 80%未満 | まだいけるよ |
| 80%以上、100%未満 | もうちょいで上限だよ |
| 100%以上 | この枠は使い切ったよ |

![](/images/anti-token-maxxing/usage-in-pi.png)

上限が近いときだけ、リセット予定を出す。

```text
5時間枠: もうちょいで上限だよ · リセット予定 18:30
週間枠: まだいけるよ
```

知りたいのは「あと何%使えるか」ではない。「いま作業を続けられるか」だけだ。

残量を見れば使いたくなる。だったら見ない。意志の力でTokenMaxxingに勝とうとするより、ゲージを壊すほうが早い。

ちなみにだけど[Pi Coding Agent](https://pi.dev/)はこういうことが簡単にできるからおすすめ。


## 余らせろ

これはトークンをケチれという話ではない。必要なら好きなだけ使えばいい。探索でも遊びでも、目的があるなら立派な使い道だ。

ただし、トークンを使うために仕事を作るな。

利用枠はノルマではない。100%は満点でもない。必要な仕事が終わったなら、そこで終わり。

「今週は40%も余った」じゃない。

**今週の仕事は60%で済んだ。**

それでいい。むしろ、そのほうがいい。
